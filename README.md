# Web Access Worker

Release **1.0.0**, compatibility protocol **1.0**, deployment kind **aper-web-access**. This independent, dependency-free Worker acquires bounded public static documents for a user-owned Aper installation. `src/worker.js` owns authentication, exact-origin browser access, target validation, acquisition, and the versioned HTTP contract. It performs no Cloudflare management operations and has no MCP routes, search relay, rendering, persistence, extraction, or telemetry. Wrangler and Vite+ are pinned development dependencies; `pnpm-lock.yaml` locks the toolchain.

## Install and connect

The template is currently local; public publication and a real Cloudflare installer run remain pending. Do not represent the hosted installation path as verified until both are complete.

1. In Aper, open Settings → Local Tools → Web Access Worker and start setup. Aper generates a fresh 256-bit runtime secret in its separate credential vault and saves pending setup without changing an active connection.
2. Once this template is published to `ent3m/aper-web-access`, use [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/ent3m/aper-web-access) in a new tab. Cloudflare requires GitHub/GitLab integration, copies the public repository into your Git account, and lets you select the Cloudflare account. Aper does not link accounts, receive management credentials, or use a management relay or bootstrap service.
3. Set non-secret `APER_ALLOWED_ORIGIN` to the exact origin shown in Aper, for example `https://aper.run`, your self-hosted HTTPS origin, or `http://localhost:5173`. Include the scheme and development port; omit paths and trailing slash. `wrangler.jsonc` exposes the variable and preserves deployed variable overrides with `keep_vars`.
4. Explicitly copy the generated secret in Aper and paste it into Cloudflare's **secret** named `APER_RUNTIME_SECRET`. `.dev.vars.example` declares an empty value so the installer can prompt; `package.json` describes both bindings. Missing, empty, or placeholder secrets fail closed. Never put real values in template source, `vars`, deployment links, issue reports, or ordinary records.
5. Complete deployment, return to Aper manually, paste the Worker HTTPS origin, validate the endpoint, then choose Verify and connect. Setup survives tab switching and reload in the same browser. Verification checks missing and incorrect credentials are rejected, then reads authenticated kind/protocol/capability evidence and requests one static document from example.com through the Worker. This explicit verification probe may consume Cloudflare quota. No runtime secret follows redirects.

For independent command-line deployment, run `vp install --frozen-lockfile`, configure the origin in your copy of `wrangler.jsonc`, run `vp exec wrangler secret put APER_RUNTIME_SECRET` and paste the generated secret at its prompt, then `vp exec wrangler deploy`. All Cloudflare authorization remains in your CLI/account. Do not pass secrets as command arguments. Local development uses a gitignored `.dev.vars` copied from the empty example.

## Compatibility contract

| Route            | Input                                                                               | Success                                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/info`   | Runtime bearer authentication and exact configured Origin                           | `kind`, `protocolVersion`, `buildId`, `capabilities: { staticFetch, browserRun, searchRelay }`                            |
| `POST /v1/fetch` | Same authentication/origin; JSON containing only `{ "url": "https://example.com" }` | `requestedUrl`, `finalUrl`, `status`, `contentType`, complete decoded `body`, ordered `redirects: [{ from, to, status }]` |

Protocol major 1 preserves these operations and meanings; additive minor fields may be ignored. Breaking changes require another major/route family. Build identity is independently versioned with the template release. Compatible older or user-modified deployments remain eligible; reported build and capabilities are compatibility observations, not source attestations or ongoing service-health guarantees. The hosted installer uses the public repository URL; no immutable source pin is claimed. A user's repository copy does not automatically track Aper releases. Review the offered release and your own changes before updating.

Errors are non-2xx JSON `{ "error": "code" }`; raw upstream bodies, exceptions, headers, and secrets are never logged or returned as errors. Codes distinguish origin/auth/configuration, invalid request/target, forbidden target, redirect limit, header/body limits, unsupported documents, encoding, deadline/cancellation, and acquisition failure. Browser CORS/CSP/network failures can be ambiguous. Preflight permits only the method for the route and Authorization/Content-Type; CORS is additional browser control, never authentication. Responses disable caching.

## Acquisition constraints and rationale

Acquisition constructs a GET with fixed textual Accept and User-Agent; it forwards no incoming cookies, credentials, arbitrary headers, body, or browser session. Only HTTP(S) DNS names on default ports are accepted. IP literals (including public ones), single-label/local/reserved names, URL credentials, and unsafe schemes are rejected. Every manually followed redirect is validated again. Limits are 8,192 URL characters, 10 KB input, five redirects, 32 KB observed response headers, 2 MB acquired bytes, and a 15-second total deadline. Only complete HTTP 200 HTML/XHTML/plain text is accepted. Unsupported content, partial responses, oversize bodies, and decoding errors fail instead of silently truncating. Charset comes from HTTP or defaults to UTF-8; extraction and fidelity assessment belong in Aper.

`global_fetch_strictly_public` ensures public routing rather than zone-origin shortcuts. Workers exposes no trustworthy application-controlled DNS pinning here, so hostname checks and platform public egress are defense in depth, not a claim of complete DNS-rebinding protection. Header limits apply after platform header acquisition. There is no arbitrary proxy/tunnel interface, but anyone holding the runtime secret and sending the configured Origin can consume public-fetch quota; CORS does not constrain non-browser clients. Platform account limits apply, and the owner controls costs and secret rotation.

## Lifecycle and verification

Replacement stages an independently authenticated deployment and verifies it before switching local configuration. Failed or cancelled setup leaves the last usable connection and user-modified infrastructure intact. Disconnect removes Aper's local connection only; it cannot revoke the remote secret or delete the Worker. Perform deletion and remote rotation explicitly in Cloudflare. Captured Aper bindings retain endpoint and credential identity so configuration changes do not retarget them. Web and MCP must use separate deployments, runtime secrets, protocols, routes, and capability configuration.

Run `vp check --fix`, `vp test`, `vp build`, then `vp exec wrangler deploy --dry-run --outdir dist/deploy`. Tests exercise authentication, CORS policy, target/redirect restrictions, request construction, bounds, encoding, and sanitized failure. Aper's Web and Application Configuration tests cover compatibility and persistent replacement/cancellation/capture. From the adjacent Aper repository, `vp exec node scripts/verify-web-worker-browser.mjs` runs Chromium against a real local HTTP/CORS boundary with deterministic public-document acquisition. It does not prove Cloudflare hosting.

Before enabling Aper's installer launch, publish and inspect this release, complete Deploy to Cloudflare with account/Git selection, verify editable origin and explicit secret transfer, then connect from the actual Aper origin. Verify missing/wrong/correct credentials, authenticated info, a real static fetch, wrong-origin rejection, failed replacement preservation, and disconnect. Record only sanitized deployment URL, origin, observed release/protocol/capabilities, dates, and outcomes. This live installation is still pending; no successful hosted run is claimed.
